A bounded compatibility review

  • Detects removed operations, newly required inputs, type and enum changes, and selected schema constraints.
  • Checks requests and responses in opposite compatibility directions.
  • Flags unsupported constructs and unresolved references for review. External references are never fetched.
  • No findings does not prove compatibility. Runtime behavior and generated SDKs still need testing.
Why can an added response value break a client?

An old client may handle only “queued,” “shipped,” and “delivered.” Adding “returned” to the response enum can break an exhaustive switch. Accepting an extra request enum value, however, preserves the old inputs.
